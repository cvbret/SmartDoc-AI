# PostgreSQL 事务与查询指南

事务将一组数据库操作作为一个整体。BEGIN 开始事务，COMMIT 提交成功后变更生效，ROLLBACK 放弃本事务尚未提交的变更。转账中的扣款和入账需要放在同一个事务中，才能避免只完成其中一步；应用还需检查业务条件。

事务原子性针对事务内的数据库操作，不会自动把外部 Redis 命令包括进来。只有确认数据库提交成功，应用才能把这次数据库更新视为已完成。

主键标识表中的一行，要求唯一且非空。一张表有一个主键约束，可以由多个列共同组成。索引可以帮助某些查询减少扫描，但占用存储，并增加写入时维护索引的工作；不是越多越好。

SELECT 不带 ORDER BY 时不能依赖结果的固定顺序。需要按时间排序时应明确 ORDER BY；如果多个记录时间相同且需要稳定分页，可再添加唯一的 id 作为第二排序依据。仅按可能重复的时间字段排序，不能保证这些同时间记录的相对顺序。
