# HTTP 资料更新接口指南

本知识库的用户资料接口约定：PUT 使用请求体中的完整表示替换目标资料，客户端必须提供完整资料；不能把遗漏字段理解为自动保留。PATCH 只更新提交的字段，未提交的字段保持不变。例如只改昵称而保留头像，应发送 PATCH。

GET 用于读取资料，不应被设计为修改资料的操作。POST 常用于向集合创建新资源，重复提交可能创建多个资源。不能仅凭使用 POST 就假定请求幂等。

幂等描述的是重复执行相同请求与执行一次对服务器产生的预期效果相同，不要求每次响应内容或状态码相同。按整体替换语义实现的 PUT 是幂等的。PATCH 是否幂等取决于操作：把昵称设为同一个值可幂等，而每次将计数加一不是幂等操作。

接口设计需把读取、局部更新和整体替换的语义写清楚。这里的 PATCH 字段保留规则是本资料接口的明确约定，不能自动推广到所有接口的任意补丁格式。
