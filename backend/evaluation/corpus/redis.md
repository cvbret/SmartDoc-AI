# Redis 缓存生命周期指南

EXPIRE key seconds 为已经存在的键设置以秒为单位的过期时间，例如 EXPIRE profile 60。在期限内键仍可读取，到期后自动失效。DEL key 立即删除指定键，不等待到期；返回实际删除的键数。

PERSIST key 移除已有过期时间，保留键和值，让键不再因这次 TTL 到期而失效。它不会延长成一个新的固定倒计时，也不会修改值。

TTL key 查询剩余生存时间，以秒为单位。返回 -1 表示键存在但没有过期时间，返回 -2 表示键不存在。普通非负结果表示剩余秒数。

在本示例应用中，PostgreSQL 是资料的权威存储，Redis 只保存缓存副本。数据库更新成功提交后，应用删除对应缓存键；下次读取再从数据库加载。这是应用约定，不是 Redis 自动保证的跨系统事务。如果删除缓存失败，需要重试或等待已有 TTL 到期；在此之前可能读到旧缓存。
